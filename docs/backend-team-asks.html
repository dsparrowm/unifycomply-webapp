These items were taken out of the notes for the UnifyComply team. That pack asks only for permission to add or change screens. This note is what the API still has to provide before those screens can tell the truth.

Answered 2 October 2026. Status below is theirs: live, partial, or not built.

1. The review clock does not start on approve — live

Approve now sets lastReviewedAt to now and nextReviewAt to now plus the app’s expiry days. Reject, offboard, or a return to review clears nextReviewAt. Due book is status=onboarded and nextReviewAt <= now. Customers approved by hand before 2 October can still have nextReviewAt: null until a backfill. Show that as “no review scheduled”, not an error.

2. A second run is not marked as a refresh — partial

customerId is live on GET /v1/verifications, /verifications/kyc, and /verifications/kyb. cycle, trigger, reason, and the 409 for a refresh on a customer who is not onboarded are not built. Until then, the reason a file returned to review is on the workflow event: detail.trigger and detail.reason.

3. Send-back without blocking the customer — live

Request resubmission is POST /v1/customers/{kyc|kyb}/{customerId}/request-resubmission with { issues, instructions? }. Issues load from resubmission-issues. The list pill stays Pending and the row carries resubmission. Escalate is POST …/escalate with { notes, userId? }. A high-risk approve returns 409 escalation-required until the case has been escalated.

4. Assignment has no write — live

PUT /v1/verifications/{workflowId}/assignee with { userId } or { userId: null }. Queue rows return assignedTo: { id, name }. Cases use POST /v1/transactions/{transactionId}/actions/assign-case.

5. Investigation dropdowns are not in the option registry — live

New option keys: case-resolution-types, case-actions-taken, pnd-resolution-types, pnd-statuses, investigation-entity-types, investigation-risk-levels, sar-statuses. Send the option value. Keep the words already on the screen when a label differs.

6. Reads the designed screens still cannot fill — not built

They treat these as new features. Their suggestion to hide Lookup, hide Bank Analysis, and drop the standalone AML module is a screen change, so the screens stay until the UnifyComply team says otherwise.

7. Behaviour the guide already marks as incomplete — partial

SAR draft now returns 503 with data.code === "ai-not-configured". Trigger rows carry evaluated. Two dead rules still wait on numbers from Compliance. Extra webhooks are not built, except workflow.resubmission-requested, which is live.
